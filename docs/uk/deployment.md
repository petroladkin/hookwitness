# Налаштування й розгортання

Як тримати Hookwitness довше, ніж один вечір: у Docker з даними в томі, з
параметрами, ключем секретів і за зворотним проксі.

## Docker

<!-- docs-check: skip: starts a container; scripts/docker-smoke.sh runs this command in CI -->
```sh
docker run -d --name hookwitness -p 127.0.0.1:8080:8080 -v hookwitness:/data \
  ghcr.io/petroladkin/hookwitness:0.1
```

Інтерфейс — на <http://127.0.0.1:8080/admin/>; вебхуки йдуть на будь-який
інший шлях порту 8080. Образи зібрано для linux/amd64 і linux/arm64, з такими
тегами:

- `:0.1` (його вживають ці сторінки) іде за найновішим релізом 0.1.x:
  виправлення, без несумісних змін;
- `:X.Y.Z`, наприклад `:0.1.0`, — один реліз, він ніколи не змінюється;
- `:latest` — найновіший реліз, хоч якої версії;
- `:edge` іде за гілкою розробки, без жодних обіцянок.

Кандидати в релізи (`:0.1.0-rc.1`) мають лише власний тег.

### Тримайте дані в томі

Усе, що зберігає Hookwitness (ендпоінти, їхня поведінка, секрети, упіймані
запити), лежить у `/data`: база даних і, якщо не задано
`HOOKWITNESS_SECRET_KEY`, ключ, яким запечатано секрети
(`/data/hookwitness.db.key`).

**Завжди монтуйте `/data`.** Без `-v hookwitness:/data` дані живуть у
власному шарі контейнера: після `docker rm` і нового `docker run`
(оновлення, змінений прапорець) все починається з нуля, усі ендпоінти
зникають. Іменований том, як вище, переживає контейнер.

Якщо замість іменованого тому каталог хоста, віддайте його користувачу
образу (`chown 65532:65532 <dir>`) або запускайте з
`--user "$(id -u):$(id -g)"`.

Робіть резервну копію бази й ключа разом: база, відновлена без свого ключа,
зберігає запити, але втрачає секрети.

### Compose

```yaml
services:
  hookwitness:
    image: ghcr.io/petroladkin/hookwitness:0.1
    ports: ["127.0.0.1:8080:8080"]
    volumes: ["hookwitness:/data"]
    restart: unless-stopped
volumes:
  hookwitness:
```

### Образ

- Працює від непривілейованого користувача без оболонки, а також працює з
  `--read-only --tmpfs /tmp`.
- Має перевірку здоров'я (`hookwitness health`, що питає `/healthz`);
  `docker ps` її показує.
- Несе підписане походження збірки (provenance) і SBOM:
  `gh attestation verify oci://ghcr.io/petroladkin/hookwitness:0.1 --owner petroladkin`.
- `make image` збирає його локально; `make image-smoke` запускає той самий
  сценарій, що й CI.

## Параметри

Параметри задаються прапорцями або змінними середовища; прапорець має
перевагу. У Docker передавайте змінні: `-e HOOKWITNESS_RETENTION=5000`.

| Прапорець | Змінна | Типово | Що означає |
|---|---|---|---|
| `-addr` | `HOOKWITNESS_ADDR` | `127.0.0.1:8080` (в образі: `:8080`) | адреса, яку слухає сервер |
| `-db` | `HOOKWITNESS_DB` | `hookwitness.db` (в образі: `/data/hookwitness.db`) | файл бази даних |
| `-log-format` | `HOOKWITNESS_LOG_FORMAT` | `text` | `text` або `json` |
| `-max-body` | `HOOKWITNESS_MAX_BODY` | `10MiB` | найбільше тіло, що зберігається, у байтах або з `KiB`, `MiB`, `GiB`, щонайбільше `512MiB`; більше отримує `413` і не зберігається |
| `-max-inflight` | `HOOKWITNESS_MAX_INFLIGHT` | більше з `256MiB` і подвоєного `-max-body` | скільки байтів тіл запитів читається одночасно; тіло, що не вміщається, отримує `503` з `Retry-After: 5` і зберігається без тіла; не менше за `-max-body` |
| `-retention` | `HOOKWITNESS_RETENTION` | `1000` | скільки запитів зберігати на ендпоінт і стільки ж без ендпоінта |
| `-admin-addr` | `HOOKWITNESS_ADMIN_ADDR` | немає | окрема адреса адмін-інтерфейсу (host:port) для інтерфейсу, API і MCP; без неї вони живуть під `-admin-prefix` на `-addr` ([нижче](#адмінка-на-окремому-порту)) |
| `-admin-prefix` | `HOOKWITNESS_ADMIN_PREFIX` | `/admin` | де живуть інтерфейс і API; `/` (корінь) лише разом з `-admin-addr` |
| `-public-url` | `HOOKWITNESS_PUBLIC_URL` | немає | URL, за яким відправники дістаються шляхів для вебхуків, наприклад `https://hooks.example.com`: на ньому будуються адреси вебхуків, які показують інтерфейс і API (за проксі, тунелем чи з переназначеними портами) |
| `-admin-hosts` | `HOOKWITNESS_ADMIN_HOSTS` | немає | імена хостів, на які відповідають інтерфейс і API, через кому |
| `-max-wait` | `HOOKWITNESS_MAX_WAIT` | `5m` | найдовша затримка відповіді чи утримання таймауту, від 1s до 1h |
| `-import` | `HOOKWITNESS_IMPORT` | немає | файл налаштування, що застосовується на кожному старті: його ендпоінти створюються або їхня поведінка замінюється, секрети зберігають значення ([Як поділитися налаштуванням](sharing.md#відомі-ендпоінти-без-кліків)) |
| `-replay-allow` | `HOOKWITNESS_REPLAY_ALLOW` | будь-яка адреса, крім link-local і метаданих хмари | куди можна повторювати упіймані запити: імена хостів, `host:port`, адреси чи CIDR через кому; `none` вимикає повтор ([Повтор запиту](replay.md#які-адреси)) |
| `-mcp-max-sessions` | `HOOKWITNESS_MCP_MAX_SESSIONS` | `32` | скільки MCP-сесій може бути відкрито одночасно; на ще одну `initialize` отримує `503`, а місце звільняється, коли сесію закрито або вона 30 хвилин простоює; `0` — без обмеження ([MCP](agents.md#mcp)) |
| `-trusted-proxies` | `HOOKWITNESS_TRUSTED_PROXIES` | немає | зворотні проксі (адреси чи CIDR через кому), чий `X-Forwarded-For` називає клієнта, для обмеження входу ([Користувачі й вхід](access.md#за-зворотним-проксі)) |
| — | `HOOKWITNESS_ADMIN_USER`, `HOOKWITNESS_ADMIN_PASSWORD_FILE` | немає | перший адміністратор, створений на старті в базі без користувачів ([Користувачі й вхід](access.md)) |
| — | `HOOKWITNESS_API_TOKEN_FILE` | немає | файл з машинним токеном для API і MCP ([Користувачі й вхід](access.md#машинний-токен)) |
| — | `HOOKWITNESS_SECRET_KEY` | немає | ключ секретів (нижче); без нього — файл ключа `<db>.key` |

База виростає щонайбільше приблизно до (ендпоінти × `-retention` ×
`-max-body`) плюс `-retention` × 64 KiB для реєстру Unmatched, який зберігає
лише перші 64 KiB тіла.

Ctrl-C або SIGTERM зупиняє сервер акуратно: запити в роботі завершуються,
утримання таймаутів закінчуються.

### Ключ секретів

Секрети перевірок ендпоінтів залежать від 32-байтового ключа: ним
шифруються ключі підпису і хешуються токени й паролі. Цей ключ:

- `HOOKWITNESS_SECRET_KEY`, 32 байти в base64 (`openssl rand -base64 32`).
  Його читають лише із середовища, щоб він не з'являвся в списку процесів;
- або, якщо його не задано, файл ключа поруч із базою (`<db>.key`,
  створюється з правами 0600 під час першого запуску).

Переносьте ключ разом із базою. База, відкрита з іншим ключем, зберігає все,
крім секретів: ключі підпису неможливо розшифрувати (їхні перевірки дають
**n/v**), а збережені токени ніколи не збігаються. Сервер попереджає про це
під час запуску; див. [Розв'язання проблем](troubleshooting.md).

## Доступ з інших машин

Поки немає жодного користувача, адмінка (інтерфейс, API і MCP) **не має
входу**: тримайте її на localhost або додайте користувача, перш ніж
публікувати ([Користувачі, вхід і токени](access.md)). Навіть з увімкненим
входом безпечніше публікувати лише шляхи для вебхуків.

- `-p 127.0.0.1:8080:8080` лишає його на цьому хості. `-p 8080:8080`
  публікує в мережу.
- Інтерфейс і API відповідають, лише коли їх відкрито за IP-адресою чи
  `localhost`, тож ворожа вебсторінка не дістанеться до них, спрямувавши
  свій домен на ваш сервер (DNS rebinding). За проксі з іменем дозвольте це
  ім'я: `-e HOOKWITNESS_ADMIN_HOSTS=hooks.example.com`. Шляхи для вебхуків
  відповідають на будь-яке ім'я.
- Там, де до сервера можуть дістатися сторонні, публікуйте все, крім
  префікса адмін-інтерфейсу (`/admin`), або винесіть адмінку на окремий
  порт і публікуйте лише порт для вебхуків (наступний розділ).

![Відповідь на ім'я хоста, якого не дозволено](../images/host-refused.webp)

### Адмінка на окремому порту

Типово один порт робить усе: шляхи для вебхуків і, під `/admin`, інтерфейс,
API і MCP. Задайте `HOOKWITNESS_ADMIN_ADDR`, щоб дати адмінці окремий порт;
тоді на порту для вебхуків лишаються тільки вони і `/healthz`, а будь-який
інший шлях там ловиться як вебхук, `/admin/…` теж. Публікуйте порт для
вебхуків, а порт адмінки тримайте на localhost:

<!-- docs-check: skip: starts a container; scripts/docker-smoke.sh runs this layout in CI -->
```sh
docker run -d --name hookwitness -p 8080:8080 -p 127.0.0.1:8081:8081 \
  -e HOOKWITNESS_ADMIN_ADDR=:8081 -e HOOKWITNESS_ADMIN_PREFIX=/ \
  -e HOOKWITNESS_PUBLIC_URL=http://hooks.example.com:8080 \
  -v hookwitness:/data ghcr.io/petroladkin/hookwitness:0.1
```

Тоді інтерфейс за адресою <http://127.0.0.1:8081/>, API —
`http://127.0.0.1:8081/api/v1`, а MCP — `http://127.0.0.1:8081/mcp`
(`hookwitness mcp -url http://127.0.0.1:8081/mcp`). Зі звичайним префіксом
вони лишаються під `/admin` на порту адмінки. `/healthz` відповідає на обох
портах; перевірка здоров'я образу питає порт для вебхуків.

Адресам вебхуків в інтерфейсі треба знати, де відправники дістаються порту
для вебхуків. Без `HOOKWITNESS_PUBLIC_URL` вони беруть хост із `-addr`, якщо
він там названий, а інакше — хост, за яким ви відкрили інтерфейс, з портом
для вебхуків (`8080`). За проксі, тунелем чи з переназначеним портом
(`-p 9000:8080`) це вгадування хибне: задайте `HOOKWITNESS_PUBLIC_URL`.

Тепер ендпоінт може мати шлях під `/admin`. Якщо адмінка згодом повернеться
під префікс на порт для вебхуків, вона перекриє такий ендпоінт, і він нічого
не ловитиме; сервер називає такі ендпоінти в попередженні під час запуску.

## Збірка з вихідного коду

Потрібен Go 1.27 або новіший. Без клону `go install
github.com/petroladkin/hookwitness/cmd/hookwitness@latest` кладе найновіший
реліз у `$(go env GOPATH)/bin` (`@v0.1.0` — для конкретного). У клоні:

<!-- docs-check: skip: builds and starts the server this check already runs -->
```sh
make build                    # writes bin/hookwitness, a single static binary
bin/hookwitness version
bin/hookwitness serve         # listens on 127.0.0.1:8080, database ./hookwitness.db
```

`make check` також потребує компілятора C для race-детектора; сам бінарник
збирається без cgo.

`bin/hookwitness health` питає `/healthz` запущеного сервера і виходить з
кодом 0, коли він працює.

## Яка збірка працює

Усюди, де згадано Hookwitness, збірку названо як `<версія> (<коміт>)`,
наприклад `v0.1.0 (5a45bb4)`: рядок унизу сторінки Endpoints (і підказка на
логотипі на кожній сторінці), `hookwitness version` і рядок «Generated … by
Hookwitness» кожного звіту. Тож звіт, доданий до тікета, каже, яка збірка
впіймала його запити. Випущені образи кажуть свій тег (`v1.2.0 (…)`), образ
`:edge` каже `edge`, `make build` — те, що знаходить `git describe`, а збірка
без нього (`go install`, звичайний `go build`) — версію модуля, яку записав
Go: тег для релізу, псевдоверсію на кшталт
`v0.1.1-0.20261016120000-abcdef123456` між релізами або `dev`, коли її
немає.

`/healthz` дає те саме у двох полях:

```sh
curl -s http://127.0.0.1:8080/healthz | jq -r 'keys | join(" ")'
# commit status version
```
